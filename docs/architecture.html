How Football Predictions works

A per-league forecasting pipeline: data in from football-data.co.uk and ESPN, a time-weighted Dixon-Coles model fitted on it, walk-forward backtests and a live ledger to keep it honest, and an Excel report out.

2 commands8 sub-commands14 modules main classes Run, DixonColes, EspnClient, FootballData

The big picture

Both commands read src/football_predictions.toml. main.main() builds one Run per league, and every sub-command is a Run method. Run fetches data through the data-access layer, fits and evaluates the model, and writes CSV and JSON state to state/<league>/ and reports to reports/.

What update does

The feedback loop you run after each round: score what was predicted, replay the season, predict what's next, rebuild the report. Each step re-reads the data, so every new result changes the next fit.

1 · SETTLE

New results are matched to rows in ledger.csv by season, home and away, so predictions logged before kickoff get scored.

2 · BACKTEST

backtest.walk_forward() refits the model before each match date using only earlier games, then predicts that day.

3 · PREDICT

Fit on everything played so far, predict fixtures from football-data, with ESPN's schedule filling gaps, and log them.

4 · REPORT

report.write() assembles the workbook from the saved files and metrics tables.

Inside the model

Each team has an attack and a defence rating; each division (and the cup pseudo-division) has a scoring level and a home advantage. fit() estimates them by weighted Poisson maximum likelihood with a ridge penalty. predict() turns two expected-goal numbers into a full scoreline grid, and everything reported comes from that grid.

Main classes

Solid arrows are associations, dashed arrows are "creates" or "uses", and filled diamonds mean DixonColes owns its Hyper and Params. Most other modules are plain functions, listed below.
